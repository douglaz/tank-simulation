# Review: SUGGESTIONS

## Required Changes
1. **Nitrification limiters are not enforcing the spec’s shared DO/alkalinity constraints**
   - Current: [nitrogen_cycle.rs](/root/tank-simulation/crates/tank_core/src/systems/nitrogen_cycle.rs#L115) limits `aob_rate` and `comammox_rate` independently against the same pre-consumption DO pool, then subtracts both O2 costs later at [nitrogen_cycle.rs](/root/tank-simulation/crates/tank_core/src/systems/nitrogen_cycle.rs#L159). That allows combined AOB + comammox demand to exceed available DO for the tick. Alkalinity is also only debited after conversion at [nitrogen_cycle.rs](/root/tank-simulation/crates/tank_core/src/systems/nitrogen_cycle.rs#L217), so nitrification can still proceed when alkalinity is already exhausted.
   - Expected: Realized AOB/comammox/NOB conversion must be capped by the remaining shared DO budget and the remaining alkalinity budget before substrate is converted, so only the chemically supported fraction proceeds.
   - Reference: loop-4 acceptance criterion requiring nitrification to consume O2 and alkalinity stoichiometrically, and that “if TAN, nitrite, DO, or alkalinity is insufficient, only the supported fraction may convert.”

2. **Dirty-filter slowdown is not implemented**
   - Current: the nitrogen-cycle environmental factor only uses `biofilter_maturity_index` at [nitrogen_cycle.rs](/root/tank-simulation/crates/tank_core/src/systems/nitrogen_cycle.rs#L248), while filter dirtiness state is only mutated during cleaning at [engine.rs](/root/tank-simulation/crates/tank_core/src/engine.rs#L166) and never feeds back into nitrification rates. The implementation therefore models “immature” filters, but not “dirty” filters.
   - Expected: Nitrifier realization should also be reduced by filter cleanliness/clogging, or an equivalent documented dirty-filter factor, so nitrification is slower in immature or dirty filters as specified.
   - Reference: loop-4 acceptance criterion requiring Monod-style nitrification rates to be “slower in immature or dirty filters.”

## Recommended Improvements
1. Add a regression that explicitly exercises the missing limiter contract: one case with very low alkalinity and one case where AOB and comammox compete for the same tiny DO pool. The current added tests cover downstream outcomes, but not this acceptance criterion directly.

2. Tighten `comammox_vmax_fraction` validation in [presets.rs](/root/tank-simulation/crates/tank_data/src/presets.rs#L208) to reject values above `1.0`; the spec requires comammox to be the lower-`vmax` TAN path, and the schema currently allows presets that violate that.
