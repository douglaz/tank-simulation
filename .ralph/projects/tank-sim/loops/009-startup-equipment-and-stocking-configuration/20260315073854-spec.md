# Feature: Startup Equipment and Stocking Configuration

## Description
The prompt requires that "the MVP must allow a user to choose substrate, source water, plants, filter, light, heater, and shrimp count." Currently, the TUI startup screen only exposes Scenario, Tank Size, and Fill Height — all other choices (source water, substrate, plants, hardware, shrimp) are bundled into the 3 scenario presets with hardcoded defaults for hardware and zero initial shrimp. This feature adds per-component selection fields to the startup configuration screen, extends the scenario materialization path to apply hardware and stocking overrides, and ensures heater-enabled tanks and non-zero initial shrimp populations are achievable from first launch.

## Acceptance Criteria
- [ ] The startup configuration screen includes independently selectable fields for: source water profile, substrate preset, plant selection, filter on/off, light photoperiod, heater enabled + setpoint, aeration on/off, and initial shrimp count
- [ ] Source water field cycles through all 4 available profiles (`soft_acidic`, `moderate`, `hard_shrimp`, `ro_like`) independently of the scenario
- [ ] Substrate field cycles through at least 4 preset combinations: `inert_sand`, `inert_gravel`, `active_planted`, `active_planted + coarse_porous` (two-layer)
- [ ] Plant selection field allows choosing: `FastStem only`, `RootFeedingRosette only`, `Both guilds`, or `None`
- [ ] Filter field toggles enabled/disabled (defaults to enabled)
- [ ] Light field cycles through photoperiod presets (e.g., `6h`, `8h`, `10h`, `12h`)
- [ ] Heater field cycles through options: `Off`, `24°C`, `25°C`, `26°C` (enabled with given setpoint)
- [ ] Aeration field toggles enabled/disabled (defaults to disabled)
- [ ] Initial shrimp count field allows setting 0, 5, 10, 15, or 20 shrimp
- [ ] Scenario field is retained but acts as a template — selecting a scenario sets default values for the new fields, which the user can then override
- [ ] When a scenario is changed, the override fields reset to that scenario's defaults
- [ ] The materialization path applies the user's hardware and stocking choices to the `TankState` after scenario materialization
- [ ] A tank launched with heater enabled starts with `HeaterState.enabled = true` and the selected setpoint
- [ ] A tank launched with initial shrimp count > 0 starts with that many adults in the `AnimalState`
- [ ] The startup summary panel updates to reflect the user's current selections (not just the scenario defaults)
- [ ] All existing acceptance tests continue to pass (they use programmatic scenario materialization, not the TUI startup path)
- [ ] A new integration test verifies that a state materialized with heater enabled and 10 initial shrimp has `hardware.heater.enabled == true` and `animals.adults == 10`

## Files to Modify/Create

- `crates/tank_scenarios/src/lib.rs` — Add a new `StartupOverrides` struct and a `seeded_state_with_full_overrides` function (or extend `seeded_state_with_overrides`) that accepts hardware settings, initial shrimp count, source water override, substrate override, and plant selection override; apply these after base scenario materialization
