# Feature: Workspace Skeleton, Core Types, RNG, and Save/Load

## Description
Bootstrap the Cargo workspace with all four crates (`tank_core`, `tank_data`, `tank_tui`, `tank_scenarios`), define the full domain type hierarchy (`TankState`, `TankGeometry`, `WaterState`, `PlayerAction`, `SimEvent`, `TankSnapshot`, etc.), implement the deterministic RNG wrapper using `ChaCha8Rng`, wire up JSON save/load with schema and app versioning, and establish the `SimulationEngine` trait with a minimal concrete implementation that can apply actions to a queue and step through empty ticks. This is Milestone 1 from the spec — the foundation every subsequent feature builds on.

## Acceptance Criteria
- [ ] Cargo workspace compiles with four crates: `tank_core`, `tank_data`, `tank_tui`, `tank_scenarios`; `tank_core` has no TUI dependencies
- [ ] `TankGeometry` struct is defined with all fields (`length_cm`, `width_cm`, `height_cm`, `fill_height_cm`, `glass_thickness_mm`, `open_top`) and derives `water_volume_l`, `surface_area_cm2`, `footprint_area_cm2`, `wall_area_cm2`, `mean_depth_cm`, `surface_area_to_volume_ratio`, `wall_area_to_volume_ratio`
- [ ] `WaterState` stores all required dissolved pools as total amounts (`ammonia_total_mg_n_total`, `nitrite_mg_n_total`, `nitrate_mg_n_total`, `phosphate_mg_p_total`, `dissolved_oxygen_mg_total`, `dissolved_inorganic_carbon_mg_c_total`, `dissolved_organic_carbon_mg_c_total`, `dissolved_organic_nitrogen_mg_n_total`, `alkalinity_meq_total`, and all 7 ion totals: Ca, Mg, Na, K, HCO3, Cl, SO4)
- [ ] `TankSnapshot` derives all display values: `tan_mg_l`, `nh3_mg_l`, `nitrite_mg_l`, `nitrate_mg_l`, `phosphate_mg_l`, `do_mg_l`, `gh_d`, `kh_d`, `tds_mg_l`, `conductivity_us_cm`, `ph` using the exact formulas from the spec
- [ ] `PlayerAction` enum defined with all 12 variants and validation logic that returns typed `SimError` (percentages in `0.0..=1.0` or `0.0..=100.0` as specified, non-negative grams/counts)
- [ ] `SimEvent` struct with `day`, `hour`, `severity`, `kind`, `cause_codes`, `summary`; `EventKind` enum with all 13 required variants; `EventSeverity` enum (Info, Warning, Critical)
- [ ] `SimSeed(u64)` wraps `ChaCha8Rng`; the RNG is stored in `TankState`; no thread-local RNG is used anywhere in `tank_core`
- [ ] `SimulationEngine` trait implemented with `apply_action`, `step_hours`, `snapshot`, `full_state`; actions are queued and processed at the start of each hourly tick in insertion order
- [ ] `TankState` contains all top-level sub-states: geometry, environment (ambient temp, hour-of-day, day counter), hardware (light, heater, filter, aeration), water, substrate layers, filter state, plant guild states, algae state, microbe state, microfauna state, animal (shrimp) state, detritus state, event log, and RNG
- [ ] Save file is JSON containing: `schema_version`, `app_version`, full `TankState`, queued actions, and serialized RNG state
- [ ] `save_load_roundtrip` test: create a state with a non-default seed, serialize to JSON, deserialize, and assert the restored state is identical (field-by-field equality)
- [ ] `determinism_basic` test: two engines with the same seed stepping 24 hours produce identical snapshots
- [ ] `action_validation` test: invalid actions (negative grams, out-of-range percentages, etc.) return `Err(SimError)` with descriptive variants
- [ ] `action_queuing` test: multiple actions queued for the same tick are processed in insertion order
- [ ] Invariant checks run after every `step_hours` call: no negative mass pools, no negative populations, index values clamped to `0.0..=1.0`, temperature above `0.0 C`
- [ ] `tank_data` crate has TOML deserialization scaffolding with `serde` and `toml`; preset structs for source water, substrate, plant, and shrimp profiles are defined (loading actual preset files is included)
- [ ] All preset TOML files created: source water (`soft_acidic`, `moderate`, `hard_shrimp`, `ro_like`), substrate (`inert_sand`, `inert_gravel`, `active_planted`, `coarse_porous`), plants (`fast_stem`, `root_rosette`), shrimp (`neocaridina_davidi`), process parameters (one default pack), and scenarios (`nano_cycle`, `medium_planted`, `warm_room`)
- [ ] `open_top = false` stores a configurable lid factor (default `0.25`) that will reduce surface exchange rates when those systems are implemented
