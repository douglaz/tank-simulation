# Implementation Response (Iteration 1)

## Changes Made
1. **Water-change profile validation (required):** Added `SourceWaterProfile::validate(profile_id)` method in `crates/tank_core/src/types/source_water.rs` that rejects non-finite or negative chemistry values and non-finite/non-positive temperature. Added `SimError::InvalidSourceProfile { id, field, value }` variant in `crates/tank_core/src/types/actions.rs`. Updated `validate_water_changes` in `crates/tank_core/src/systems/water_change.rs` to call `profile.validate()` on every resolved profile before any mutations occur. This ensures that both unknown and invalid resolved profiles are caught atomically before `step_one_hour` processes any actions, preserving the partial-failure invariant: `TankState`, queued actions, RNG state, clock, and event log remain exactly unchanged on failure.

2. **Invariant hardening:** Updated `check_non_negative` in `crates/tank_core/src/invariants.rs` to also reject non-finite (`NaN`, `Inf`) values, preventing NaN propagation through the simulation state even outside the water-change path.

3. **Strict preset enum validation (recommended):** Changed `crates/tank_scenarios/src/lib.rs` to return `PresetError::Validation` instead of silently defaulting to `InertSand`/`FastStem` when encountering unsupported substrate kind or plant guild strings.

4. **Regression tests:** Added two new tests in `crates/tank_core/tests/water_change_mass_balance.rs`:
   - `invalid_resolved_profile_returns_error_and_leaves_state_unchanged` — inserts a profile with `NaN` calcium, queues feed + water change, asserts `InvalidSourceProfile` error and full state immutability (day, hour, event_log, water chemistry, detritus).
   - `invalid_resolved_profile_negative_chemistry_returns_error` — inserts a profile with negative nitrate, asserts `InvalidSourceProfile` error.
