# Feature: TUI MVP, Scenario Integration, and Full Regression Suite

## Description
Implement the terminal user interface (Milestone 7) as a playable binary that lets users choose a scenario, run the simulation forward, perform all player actions, and observe chemistry/biology/events across five screens. Wire the TUI to consume `TankSnapshot` and dispatch `PlayerAction` via the `SimulationEngine` trait—never mutating state directly. Add a `tank_tui` binary entry point that integrates `tank_scenarios` for game setup. Strengthen the acceptance test suite to fully meet the 10 mandatory test specifications (in particular: extend `determinism_same_seed` to 720 hours with an action schedule, and extend `overfeeding_effects` to assert on detritus and nightly minimum DO, not only algae nuisance).

## Acceptance Criteria
- [ ] Running `cargo run -p tank_tui` launches an interactive terminal application
- [ ] On startup, the user can select from the three preset scenarios (`nano_cycle`, `medium_planted`, `warm_room`) and choose a tank size / fill height
- [ ] **Overview screen** displays: day/hour, temperature, pH, DO, TAN, NH3, nitrite, nitrate, plant status summary, shrimp status summary, and active warnings
- [ ] **Chemistry screen** displays detailed chemistry values (all derived display values: GH, KH, TDS, conductivity, phosphate, DIC) and recent per-tick trend indicators (arrows or sparklines) for at least pH, TAN, DO, and temperature
- [ ] **Biology screen** displays: plant guild biomasses and health, algae/periphyton biomass and nuisance index, shrimp counts (adults/juveniles/berried), condition/molt-stress/reproductive-readiness indices, biofilter maturity summary (AOB/NOB/comammox biomass or maturity proxy), and a microfauna summary
- [ ] **Actions screen** provides input forms for all 12 `PlayerAction` variants: Feed, WaterChangePercent (with source profile selection), TrimPlants, SiphonDetritus, CleanFilter, AddShrimp, RemoveShrimp, ChangePhotoperiod, ChangeLightIntensity, ChangeHeaterSetpoint, ChangeAmbientTemperature, ChangeAeration
- [ ] **Log screen** displays chronological event list from `TankSnapshot.recent_events` with severity coloring (Info=dim, Warning=yellow, Critical=red) and cause codes
- [ ] Keyboard controls: Tab/number keys to switch screens; `h` to step 1 hour, `d` to step 1 day, `w` to step 1 week; space to toggle pause/auto-advance; `s` to save, `l` to load; `q` to quit
- [ ] Auto-advance mode steps 1 hour per render tick (roughly 100–200ms interval) and can be paused/resumed with space bar
- [ ] Save writes a JSON save file (via `tank_core` serialization) to a user-visible path; load restores from that file and resumes deterministically
- [ ] The TUI only reads `TankSnapshot` for display and dispatches `PlayerAction` through `SimulationEngine::apply_action`—it never directly mutates `TankState` fields
- [ ] Validation errors from `apply_action` are displayed as transient status messages in the UI, not panics
- [ ] `determinism_same_seed` acceptance test runs 720 hours with a non-trivial action schedule (feed, water change, ambient temperature change) and asserts serialized snapshot identity
- [ ] `overfeeding_effects` acceptance test compares control vs. overfed tanks for 14 days and asserts: (a) overfed has higher detritus, (b) overfed has lower nightly minimum DO, (c) overfed has higher algae nuisance index
- [ ] All 10 mandatory acceptance tests pass under `cargo test --workspace`
- [ ] `cargo clippy --workspace` and `cargo fmt --check` pass cleanly
