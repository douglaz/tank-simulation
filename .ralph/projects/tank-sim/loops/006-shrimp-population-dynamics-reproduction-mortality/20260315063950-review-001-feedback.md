## Required Changes
1. **Clutch resolution / egg progress**: The shrimp lifecycle still violates the clutch-resolution invariant.
   - Current: [`step_daily_shrimp`](file:///root/tank-simulation/crates/tank_core/src/systems/shrimp.rs) calls [`spawning`]( /root/tank-simulation/crates/tank_core/src/systems/shrimp.rs#L250 ) before [`egg_development`]( /root/tank-simulation/crates/tank_core/src/systems/shrimp.rs#L298 ), uses one shared `egg_progress_days` for all berried females, then resolves all current `berried_females_count` together and resets progress to `0.0` at [shrimp.rs#L373]( /root/tank-simulation/crates/tank_core/src/systems/shrimp.rs#L373 ). A female that becomes berried late in the cycle, or even on the same daily tick, can therefore hatch/fail immediately with the older cohort.
   - Expected: Only completed clutches should resolve. Later berried females need separate cohort/progress tracking or an equivalent aggregate model that preserves “only the resolved clutch leaves `berried_females_count`” and “`egg_progress_days` resets only for completed clutches.”
   - Reference: Loop 6 acceptance criteria for “Egg development advances daily” and the clutch-resolution failure invariant.

2. **`thermal_reproduction_penalty` acceptance test**: The added regression does not match the required acceptance test.

   - Expected: After 60 days, the `30 C` tank must end with at least `20%` lower reproductive readiness and fewer juveniles than the `25 C` tank, matching the loop spec and prompt acceptance test.
   - Reference: Prompt §14.9 `thermal_reproduction_penalty`; loop 6 acceptance criterion for the mandatory acceptance test.

   - Expected: Add `ShrimpPreset` validation and include the new process parameters in validation so invalid loop-6 preset data cannot silently enter deterministic runtime state.
