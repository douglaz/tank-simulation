# Feature: Final Review Amendment Fixes (TS-REV-001, 003, 004, 005)

## Description
Implement the four outstanding final review amendments identified during the Loop 12 completion review. TS-REV-002 (alkalinity double-charge) is already correctly implemented via the budget mechanism. The remaining four amendments fix: (1) early validation of water-change source profiles, (2) removal of spurious DIC-driven alkalinity drift, (3) filter cleanliness decay during normal play, and (4) dissolved oxygen mixing during water changes.

## Acceptance Criteria
- [ ] **TS-REV-001** — `apply_action` rejects `WaterChangePercent` with an unknown `source_profile_id` immediately, returning a `SimError` before the action is enqueued. The step-time validation in `water_change.rs` is kept as a defensive fallback but is no longer the primary gate.
- [ ] **TS-REV-003** — `step_hourly_chemistry` in `chemistry.rs` no longer modifies `alkalinity_meq_total`. pH is recomputed from the existing alkalinity and updated DIC only. Nitrification and water changes remain the sole alkalinity drivers.
- [ ] **TS-REV-004** — `cleanliness_index` decays daily proportional to detritus load and bioload. A moderately stocked, unfed tank should see negligible decay; an overfed tank should see measurable decay within 2–4 weeks. `CleanFilter` restores `cleanliness_index` proportionally to its `intensity` parameter. The `update_daily_filter_clogging` formula is corrected so that clogging can actually accumulate during normal simulation.
- [ ] **TS-REV-005** — `apply_water_change` exchanges `dissolved_oxygen_mg_total` using the same retention/replacement pattern as other dissolved pools. Replacement oxygen is derived from saturation at the source water temperature (reusing existing DO saturation logic).
- [ ] All existing acceptance tests still pass (determinism, save/load, mass balance, tank size response, etc.).
- [ ] A new integration test `water_change_do_mixing` confirms that after a 50% water change, DO total is within 1% of the expected mixed value.
- [ ] A new integration test `filter_cleanliness_decay` confirms that after 30 days of moderate feeding with no cleaning, `cleanliness_index` is measurably below 1.0.
- [ ] A new unit test `apply_action_rejects_bad_source_profile` confirms that `apply_action(WaterChangePercent { source_profile_id: "nonexistent", .. })` returns `Err(SimError::...)` without enqueueing.
